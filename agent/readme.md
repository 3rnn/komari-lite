# Komari Lite Agent (monitoring only)

Cross-platform monitoring Agent that reports node metrics and performs probe tasks. This fork removes the remote terminal, file management, remote commands, MCP proxy, and auto-update modules. One-click deployment downloads version-matched Agent artifacts from a pinned GitHub Release.

## Features

- Reports CPU, memory, disk, network, load, process, GPU, system information, and cumulative traffic.
- Runs latency/Ping probes assigned by the panel and reports the results.
- Supports v2 protocol compression, IPv4/IPv6 connection preference, custom DNS, custom reported IPs, and network interface filtering.
- Accepts selected collection settings from the panel (interval, traffic reset day, interface/mount-point filters, memory accounting, and GPU monitoring).
- Supports Cloudflare Access Service Tokens (authentication headers on the primary connection, reports, and task results).

Removed: remote terminal, remote commands, file management, MCP proxy, auto-update/version checks, and return-path probes.

`--enable-remote-control` and `--disable-web-ssh` remain solely for compatibility with old configurations; they do not enable remote access.

## Installation

The one-click command generated by Add Node in the panel includes the panel URL and node token. The installer and Agent binary come from the matching `v1.0.61` GitHub Release:

```bash
# Linux (systemd or fresh OpenRC)
curl -fsSLo install.sh "https://github.com/3rnn/komari-lite/releases/download/v1.0.61/install.sh"
sudo bash install.sh \
  --endpoint "https://<your-panel>" \
  --token "<node-token>" \
  --install-source "https://github.com/3rnn/komari-lite/releases/download/v1.0.61" \
  --install-version 1.0.61
```

```powershell
# Windows (run in PowerShell 7.3+ / pwsh, not Windows PowerShell 5.1)
iwr "https://github.com/3rnn/komari-lite/releases/download/v1.0.61/install.ps1" -UseBasicParsing -OutFile install.ps1
.\install.ps1 --endpoint "https://<your-panel>" --token "<node-token>" --install-source "https://github.com/3rnn/komari-lite/releases/download/v1.0.61" --install-version 1.0.61
```

The installer requires `--install-source`; publish the matching binaries and installers in the GitHub Release before using these commands. Nodes must be able to reach GitHub. A Git tag alone does not publish or deploy these binaries.

## Local hardening controls

Latency tasks use at most eight workers with 32 additional admitted tasks. When
saturated, new tasks are rejected instead of allocating waiting goroutines; the
panel can observe the missing result as probe loss. Private and loopback probes
remain enabled by default. To constrain a particular Agent locally, set
`KOMARI_AGENT_PING_ALLOW_CIDRS` to comma-separated IPv4/IPv6 CIDRs, for example
`10.20.0.0/16,192.0.2.0/24,2001:db8::/32`. An invalid nonempty policy denies
probes. With a policy configured, resolved destinations are checked and pinned
before dialing and HTTP probes bypass environment proxies to enforce that policy.
Without a policy, environment proxy compatibility is retained. HTTP redirects
are never followed by probes.
This policy affects probes, not the Agent's panel connection or IP discovery.

Public IP discovery uses HTTPS only, checks successful HTTP status and parsed
IP addresses, limits each response to 64 KiB, and gives each address family one
five-second budget across all providers. GPU command execution is lazy and has
a two-second deadline with bounded output, so absent or wedged vendor tools do
not block package initialization.

On Linux systemd, `--install-service-user ACCOUNT` opts a **fresh** installation
into a pre-existing dedicated, non-root account whose primary group is also
non-root. Create/review this account separately; do not reuse an interactive or
shared account. The install directory and executable remain root-owned, the
config is root-owned and group-readable (`0640`), and only the private
`state/` directory is writable by the service. The account needs traversal
access to the installation's ancestors and any device groups required for GPU
monitoring. The sandbox preserves `/proc`, device visibility, host networking,
and `CAP_NET_RAW` for ICMP; it does not grant DAC bypass privileges for metrics
that require root. Confirm the metrics required on your host before opting in.

Existing root installations stay root. Restricted upgrades inherit their
verified account when the option is omitted. Changing an existing service's
account is refused: migrate traffic history, permissions, credentials and
required metrics explicitly rather than silently resetting its working directory.
The restricted mode is not supported by the OpenRC installer. Systemd unit
syntax and non-root raw ICMP with only ambient `CAP_NET_RAW` are covered by
isolated tests; full namespace/sandbox behavior still needs validation on the
target systemd host before production use.

Installer downloads enforce HTTPS for initial and redirected URLs, a connection
and overall deadline, and an in-flight disk cap (128 MiB for the Agent and
1 MiB for its checksum manifest), before checksum validation or service changes.

## Run manually

```bash
./komari-agent-linux-amd64 --endpoint "https://<your-panel>" --token "<node-token>"
```

## Configuration

Settings can be supplied in a JSON file, environment variables, or CLI flags. Precedence: defaults < JSON file < environment variables < explicit CLI flags.

```json
{
  "endpoint": "https://<your-panel>",
  "token": "<node-token>",
  "interval": 3,
  "ignore_unsafe_cert": false
}
```

Common settings:

| JSON field | Environment variable | CLI flag | Description |
| --- | --- | --- | --- |
| `endpoint` | `AGENT_ENDPOINT` | `--endpoint`, `-e` | Panel URL |
| `token` | `AGENT_TOKEN` | `--token`, `-t` | Node token |
| `interval` | `AGENT_INTERVAL` | `--interval`, `-i` | Collection interval (seconds) |
| `ignore_unsafe_cert` | `AGENT_IGNORE_UNSAFE_CERT` | `--ignore-unsafe-cert`, `-u` | Ignore invalid certificates (off by default) |
| `max_retries` | `AGENT_MAX_RETRIES` | `--max-retries`, `-r` | Maximum retry count |
| `reconnect_interval` | `AGENT_RECONNECT_INTERVAL` | `--reconnect-interval`, `-c` | Reconnect interval (seconds) |
| `info_report_interval` | `AGENT_INFO_REPORT_INTERVAL` | `--info-report-interval` | Basic information report interval (minutes) |
| `include_nics` | `AGENT_INCLUDE_NICS` | `--include-nics` | Only count these interfaces (comma-separated) |
| `exclude_nics` | `AGENT_EXCLUDE_NICS` | `--exclude-nics` | Exclude these interfaces (comma-separated) |
| `include_mountpoints` | `AGENT_INCLUDE_MOUNTPOINTS` | `--include-mountpoint` | Only count these mount points (semicolon-separated) |
| `month_rotate` | `AGENT_MONTH_ROTATE` | `--month-rotate` | Traffic reset day (`0` disables reset) |
| `month_rotate_time` | `AGENT_MONTH_ROTATE_TIME` | `--month-rotate-time` | Reset time `HH:MM:SS` (default `00:00:00`) |
| `month_rotate_timezone` | `AGENT_MONTH_ROTATE_TIMEZONE` | `--month-rotate-timezone` | Reset timezone (default `Asia/Shanghai`) |
| `memory_include_cache` | `AGENT_MEMORY_INCLUDE_CACHE` | `--memory-include-cache` | Include cache in memory usage |
| `memory_report_raw_used` | `AGENT_MEMORY_REPORT_RAW_USED` | `--memory-exclude-bcf` | Exclude buffers/cache from used memory |
| `enable_gpu` | `AGENT_ENABLE_GPU` | `--gpu` | Enable detailed GPU monitoring |
| `custom_ipv4` / `custom_ipv6` | `AGENT_CUSTOM_IPV4` / `AGENT_CUSTOM_IPV6` | `--custom-ipv4` / `--custom-ipv6` | Custom reported IP addresses |
| `get_ip_addr_from_nic` | `AGENT_GET_IP_ADDR_FROM_NIC` | `--get-ip-addr-from-nic` | Get reported IP from a network interface |
| `custom_dns` | `AGENT_CUSTOM_DNS` | `--custom-dns` | Custom DNS server |
| `protocol_version` | `AGENT_PROTOCOL_VERSION` | `--protocol-version` | Reporting protocol version (only `2` supported) |
| `disable_compression` | `AGENT_DISABLE_COMPRESSION` | `--disable-compression` | Disable v2 transport compression |
| `prefer_ip_version` | `AGENT_PREFER_IP_VERSION` | `--prefer-ip-version` | Preferred IP version (`4` or `6`) |
| `cf_access_client_id` | `AGENT_CF_ACCESS_CLIENT_ID` | `--cf-access-client-id` | Cloudflare Access Client ID |
| `cf_access_client_secret` | `AGENT_CF_ACCESS_CLIENT_SECRET` | `--cf-access-client-secret` | Cloudflare Access Client Secret |

See `./komari-agent-<os>-<arch> --help` for all options.

## Build

Requires Go 1.27.1 or newer. For a single platform:

```bash
cd agent
CGO_ENABLED=0 go build -trimpath -ldflags '-s -w' -o komari-agent .
```

Build artifacts for all 14 platforms and generate the panel distribution manifest:

```bash
./scripts/build-agent-release.sh 1.0.61
# Creates release/agent-1.0.61/: 14 artifacts + manifest.json + SHA256SUMS.txt
```

Upload the verified Agent binaries and both installer scripts to the `v1.0.61` GitHub Release. The optional panel-local catalog is not used by the generated one-click commands.

## Module path

`go.mod` retains the upstream module path `github.com/nuomiiiii/lite-agent`. Before publishing under your own GitHub namespace, update the module declaration and all imports, run `go mod tidy`, then commit.
