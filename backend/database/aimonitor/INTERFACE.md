# Hermes AI backend integration

Report/overview endpoints and JSON follow docs/ai-monitoring-contract.md. All admin REST reads return the raw object (`WithRaw`); RPC equivalents are `admin:getAIOverview`, `admin:getAISettings`, `admin:setAISettings` and enforce admin inside each handler as well as dispatcher.

**Agent integration requirement:** successful `agent.configResult` for a profile with `enable_hermes_ai:true` must include `enable_hermes_ai:true` in the result params. An omitted field (legacy Agent) is not acknowledgment. Add `EnableHermesAI *bool` to Agent ConfigResultParams and include the actually applied value on successful results. Failure results remain accepted without this field. `config_state` explicit true may also reconcile matching runtime settings; nil never does. Feature remains default false.

Pricing is automatic and fixed to the verified `openai-codex` / `gpt-5.6-terra` observed billing modes. It remains an API-equivalent estimate, not a subscription charge; existing snapshots are immutable. Settings objects: `{timezone,retention_days,detailed_retention_hours}`. Overview reads accept either a server-authoritative `preset` (`24H`, `7D`, `30D`, `Today`) or explicit `from`/`to` custom timestamps. Presets ignore client clock values and are bounded by the server clock; `Today` starts at the selected IANA timezone's local midnight. Explicit custom timestamps remain strictly retention-bounded. Costs/rates remain nullable when unknown.

**Coverage wire type:** optional sample `coverage` is a JSON boolean; omitted/null is unknown and cannot support rates. The Agent relay has been aligned to `*bool`. Collectors must emit a true coverage flag only when continuity is proven; omitted coverage honestly remains N/A. Backend live TPS/input TPS/output TPS/cache-read TPS/RPS use the latest continuously covered 10-second window; RPM/TPM and rolling counts use an independently covered 60-second window. Both end at the latest common fresh sample endpoint, allowing bounded relay lag. A cross-boundary delta is never split or interpolated, and missing coverage makes only the unsupported window N/A. Frontend labels must distinguish latest 10s from rolling 60s / sampled throughput. Historical daily/model/task `average_tps` remains null when full-range coverage cannot be proven; no true generation durations exist in cumulative Hermes counters.
